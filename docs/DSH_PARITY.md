## 0.2.9：真实桌面录制的兼容性修复（2026-11-14）

用户打开原生面板后，发现只显示“找到 1 份录制”。已通过 CUA 读取真实原生 DOM，确认面板挂载和目录读取成功。进一步直接检查磁盘，发现新聊天的录制已经生成，但格式为 schema 2；0.2.8 的目录和事件解析器只接受 schema 1，并把新格式静默过滤。

此前“当前聊天未产生录制”的判断不准确，依据的是旧目录索引。GUI 登录环境、桌面主程序和相关后台进程均已继承录制路径，不能把这个问题归为用户未配置或未重启。

修复版本 **0.2.9** 已构建、安装并保存为 `2994128`：支持 schema 1/2 且校验清单与事件版本一致；未知格式显示原因和数量；空页面刷新会重新匹配已绑定聊天；桌面空状态不再默认要求用户复制 CLI 命令。

- **56 项检查通过**（46 Python + 10 Node），兼容 schema 1 的真实归档验证也通过。
- 真实测试聊天 `Respond to greeting`：schema 2，1 次请求，8 项客户端输入（含工具声明）、完整上下文 138,362 字符，与原回复匹配；官方 0.169 reducer 接受该录制。当前长聊天另抽样三个请求，排除 additional_tools 后输入项数与官方一致。
- 安装版的真实录制预览、未来格式不支持提示、刷新后精确关联当前聊天均已点击通过。
- 当前原生面板仍驻留旧后端连接。已通过官方本地 WebSocket API请求 MCP 配置重读并收到确认，但当前页面仍只看到旧目录；没有重启用户桌面或后台引擎。**更新后原生连接中的最终展示尚未验收。**
